## 1. Executive Summary

Phase 10 implements the enterprise-grade **Keyword Intelligence + SEO Opportunity Engine: Factual Signals + Explainable Recommendations + Prioritization** for LocalBi, strictly adhering to the architectural requirements defined in `prompt.md` (Sections 9377–11500).

The engine enables LocalBi clients and marketing operators to receive deterministic, high-impact SEO and local visibility recommendations:
> *"What specific actions should be taken to capture high-intent local search demand, fix operational blind spots, and expand page coverage based on verified signals?"*

### Key Architectural Accomplishments:
1. **Multi-Source Signal Ingestion with Strict Provenance Separation**:
   - Ingests factual signals from Google Search Console (queries, clicks, impressions, positions), Google Business Profile (search keywords, impressions, profile completeness, unreplied reviews), Hyper Rank (geo-grid rank observations, average found rank, Top-3 and Top-10 coverage), LocalBi Lead Engine & Telephony (actual leads, phone calls, click intent), and Google Merchant Center (product errors, missing GTIN/brand attributes).
   - Strict provenance separation: GSC organic impressions are never conflated with GBP local search terms or geo-grid map ranks; telephony inbound calls are never conflated with web CTA clicks.
2. **Deterministic, Versioned Rules Engine (Zero Black-Box Scores)**:
   - 10 deterministic rules evaluate multi-source signals without opaque AI hallucinations or arbitrary black-box scores.
   - Every single recommendation is backed by explicit, auditable evidence records (`OpportunityEvidence`) detailing the source, metric name, exact numerical value, benchmark comparison, date range, and entity labels.
3. **Transparent Priority Scoring & Confidence**:
   - Transparent scoring mathematical formulas (0–100) based on verified search volume, ranking deficit, and conversion history.
   - Categorized into clear priority tiers: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW` and confidence tiers: `HIGH`, `MEDIUM`, `LOW`.
4. **Human-in-the-Loop Review Workflow**:
   - Operator review state machine: `OPEN` -> `IN_REVIEW` -> `ACCEPTED` -> `COMPLETED`.
   - Rejection requires an explicit `dismissalReason` (`NOT_RELEVANT`, `ALREADY_ADDRESSED`, `BUSINESS_DECISION`, `INCORRECT_MAPPING`, `LOW_PRIORITY`, `OTHER`).
   - Dismissals enforce a 30-day cooldown preventing spammy re-creation of rejected opportunities during background evaluations.
5. **Strict Negative Boundaries**:
   - **NO** automated AI-written blogs or autogenerated keyword stuffing.
   - **NO** automatic live page publishing or direct HTML tampering.
   - **NO** automated GBP posting or synthetic review replying.
   - Operators retain full agency with clear, explainable action plans (`UPDATE_METADATA`, `IMPROVE_EXISTING_PAGE`, `CREATE_PAGE`, `ADD_PRODUCT_TO_STORE`, `FIX_GBP_PROFILE`, `RESPOND_TO_REVIEWS`, `FIX_MERCHANT_PRODUCT`, `INVESTIGATE_RANK_DECLINE`, `IMPROVE_CTA`, `ADD_KEYWORD_TRACKING`).
6. **PostgreSQL 16 Dual-Role RLS Security**:
   - Applied Dual-Role RLS on `opportunities` and `opportunity_evidence` tables.
   - Enforces fail-closed multi-tenant isolation under `localbi_app` runtime role, bringing total protected tables across the platform to **64 tables**.

## 2. Architecture & Data Model

### 2.1 Database Schema Additions (`prisma/schema.prisma`)

1. **`Opportunity` model (`opportunities`)**:
   - `id`, `tenantId`, `brandId`, `storeId`, `webSurfaceId`, `pageId`, `productId`, `categoryId`, `keywordId`
   - `type`: `HIGH_IMPRESSIONS_LOW_CTR`, `HIGH_DEMAND_LOW_RANK`, `HIGH_CONVERSION_LOW_VISIBILITY`, `PAGE_WITH_TRAFFIC_NO_CONVERSIONS`, `MISSING_LANDING_PAGE`, `GBP_PROFILE_INCOMPLETE`, `UNANSWERED_REVIEWS`, `MERCHANT_PRODUCT_ISSUE`, `LOCAL_RANK_DECLINE`, `SEARCH_DEMAND_GROWTH`
   - `status`: `OPEN`, `IN_REVIEW`, `ACCEPTED`, `DISMISSED`, `COMPLETED`, `STALE`
   - `priority`: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`
   - `priorityScore`: `Float` (0–100)
   - `confidence`: `HIGH`, `MEDIUM`, `LOW`
   - `title`, `summary`, `actionType`, `actionPayload` (`Json?`)
   - `ruleId`, `ruleVersion`, `identityHash` (deterministic hash of ruleId + entity targets)
   - `detectedAt`, `lastEvaluatedAt`, `resolvedAt`, `dismissedAt`, `dismissalReason`, `dismissedBy`, `acceptedAt`, `acceptedBy`
   - Compound constraints:
     - `@@unique([tenantId, id])`
     - `@@unique([tenantId, identityHash])`
     - `@@index([tenantId, brandId, status, priorityScore(sort: Desc)])`
     - `@@index([tenantId, storeId, status])`
     - `@@index([tenantId, type, status])`

2. **`OpportunityEvidence` model (`opportunity_evidence`)**:
   - `id`, `tenantId`, `opportunityId`
   - `source`: `GSC`, `GBP`, `LOCAL_RANK`, `GA4`, `LOCALBI`, `MERCHANT`
   - `metric`: exact metric name (`impressions`, `clicks`, `ctr`, `average_position`, `top3_coverage`, `top10_coverage`, `average_rank`, `conversions`, `unanswered_reviews`, `lowest_rating`, etc.)
   - `value`: `Float`
   - `comparisonValue`: `Float?` (benchmark comparison)
   - `formattedValue`: `String?` (human-readable label, e.g. "1,200 impressions", "0.5% CTR vs 12% benchmark")
   - `dateRange`: `String?`
   - `entityType`: `String?` (`KEYWORD`, `PAGE`, `LOCATION`, `PRODUCT`)
   - `entityId`, `entityLabel`, `details` (`Json?`), `capturedAt`
   - Compound constraints:
     - `@@unique([tenantId, id])`
     - `@@index([tenantId, opportunityId])`

## 3. Core Engine Modules (`src/modules/intelligence/`)

1. **[opportunity-types.ts](file:///e:/project/localBi/src/modules/intelligence/opportunity-types.ts)**:
   - Enums and types for `OpportunityType`, `OpportunityStatus`, `OpportunityPriority`, `OpportunityConfidence`, `OpportunityActionType`, `DismissalReason`, `SignalSource`.
   - DTO interfaces compatible with TypeScript `exactOptionalPropertyTypes: true` and Prisma nullable semantics.
2. **[search-signal-service.ts](file:///e:/project/localBi/src/modules/intelligence/search-signal-service.ts)**:
   - `SearchSignalService.loadSignals`: Aggregates multi-source factual signals for a tenant and brand.
   - Normalized queries from GSC search term performance tables, GBP search term analytics, Hyper Rank grid runs, LocalBi lead and telephony attribution, location operational metadata, and Google Merchant Center product issue logs.
3. **[page-coverage-service.ts](file:///e:/project/localBi/src/modules/intelligence/page-coverage-service.ts)**:
   - `PageCoverageService.evaluateCoverage`: Evaluates whether published storefront, landing, category, product, or city pages exist for a given keyword, store, or product entity.
   - Detects `EXACT_STORE`, `EXACT_CATEGORY`, `EXACT_PRODUCT`, `CITY_PAGE`, `TOPICAL_MATCH`, or `NONE`.
4. **[opportunity-rule-engine.ts](file:///e:/project/localBi/src/modules/intelligence/opportunity-rule-engine.ts)**:
   - Contains 10 deterministic versioned rule evaluation methods:
     - Rule 1: `evaluateHighImpressionsLowCtr` (GSC queries with high impressions but below-benchmark CTR -> metadata updates).
     - Rule 2: `evaluateHighDemandLowRank` (High search demand in GBP/GSC with low geo-grid rank -> page improvements).
     - Rule 3: `evaluateHighConversionLowVisibility` (High real-world call/lead conversions with low local search rank -> investigate and optimize rank).
     - Rule 4: `evaluatePageWithTrafficNoConversions` (High organic landing page traffic with zero conversions -> CTA and UX improvements).
     - Rule 5: `evaluateMissingLandingPages` (Customer search volume without published landing page -> create dedicated page).
     - Rule 6: `evaluateGbpProfileIncomplete` (Missing address, phone, place ID, or sync error -> fix GBP profile).
     - Rule 7: `evaluateUnansweredReviews` (Unreplied customer reviews, weighted heavily by low ratings -> review response action).
     - Rule 8: `evaluateMerchantIssues` (Google Merchant Center product approval errors -> fix product feed).
     - Rule 9: `evaluateLocalRankDecline` (Steep drop in top-3 grid coverage compared to prior run -> investigate rank decline).
     - Rule 10: `evaluateSearchDemandGrowth` (High-growth customer search query -> add to active rank tracking).
5. **[opportunity-service.ts](file:///e:/project/localBi/src/modules/intelligence/opportunity-service.ts)**:
   - `runOpportunityEvaluation`: Evaluates all 10 rules under `TenantContext`, checks dismissal cooldowns, deduplicates via `identityHash`, and creates/updates opportunities and evidence within atomic transactions.
   - `listOpportunities`: Scoped filtering by brand, store, status, priority, type, and pagination with summary KPI statistics.
   - `getOpportunityById`: Detailed query including joined entities and ordered evidence records.
   - `updateWorkflowStatus`: Enforces human review permissions (`OPPORTUNITY_MANAGE`, `OPPORTUNITY_DISMISS`), required dismissal reasons, and timestamp recording.

## 4. API Endpoints

- `GET /api/tenants/[tenantSlug]/intelligence/opportunities`: List opportunities with filtering (status, priority, brand, store, type) and summary counts.
- `POST /api/tenants/[tenantSlug]/intelligence/opportunities`: Trigger opportunity evaluation pipeline for a brand (`brandId` in body).
- `GET /api/tenants/[tenantSlug]/intelligence/opportunities/[opportunityId]`: Detailed opportunity view with all evidence items.
- `PATCH /api/tenants/[tenantSlug]/intelligence/opportunities/[opportunityId]/workflow`: Transition status (`OPEN`, `IN_REVIEW`, `ACCEPTED`, `DISMISSED`, `COMPLETED`).
